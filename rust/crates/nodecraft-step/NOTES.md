# nodecraft-step: analytic curved primitives and trimmed planar faces — notes

Status: **implemented and validated.** `write_cylinder`, `write_cone`, `write_sphere`
and `write_torus` emit AP214 `MANIFOLD_SOLID_BREP` files that
`smlibpy.import_step(..., heal=False)` re-imports as valid solids with the expected
faces/edges/vertices, volume, area and bounds. Trimmed planar faces (outer loop + holes)
are supported by the model, reader, writer, triangulation and area/volume; a slab with a
through-hole re-imports through smlibpy as a valid 10-face solid. Nothing failed, so this
file records the topology decisions, conventions and remaining limits rather than a
blocker.

`cargo test -p nodecraft-step` → 6 unit tests + 3 analytic integration tests + 11 trimmed
planar tests pass (the analytic file covers 9 primitive cases; the trimmed file covers
triangulation, writer/reader and the smlibpy slab round-trip).

## What smlibpy writes, and what we mirror

Reference exports were produced with smlibpy 0.4.0
(`Cylinder(5, 10)`, `Cone(5, 2, 10)`, `Sphere(5)`, `Torus(8, 2)`) and read back with
the same `import_step`. The Rust writers reproduce the kernel topology, with simpler
but equivalent placements (origin-based axes instead of the kernel's rotated frames),
which re-import identically.

| Primitive | `ADVANCED_FACE` | kernel edges | kernel vertices | STEP `EDGE_CURVE`s | surfaces |
|---|---:|---:|---:|---:|---|
| cylinder | 3 (lateral + 2 caps) | 2 | 2 | 3 (2 `CIRCLE`, 1 seam `LINE`) | `CYLINDRICAL_SURFACE` + 2 `PLANE` |
| cone frustum | 3 (lateral + 2 caps) | 2 | 2 | 3 (2 `CIRCLE`, 1 seam `LINE`) | `CONICAL_SURFACE` + 2 `PLANE` |
| cone apex | 2 (lateral + base) | 1 | 2 | 2 (1 `CIRCLE`, 1 seam `LINE`) | `CONICAL_SURFACE` + 1 `PLANE` |
| sphere | 1 | 0 | 2 | 1 polar `CIRCLE` seam | `SPHERICAL_SURFACE` |
| torus | 1 | 0 | 1 | 2 seam `CIRCLE`s | `TOROIDAL_SURFACE` |

The kernel edge count is lower than the written `EDGE_CURVE` count because seam and
degenerate edges are not separate B-rep edges; smlibpy reports the same counts for its
own exports (e.g. `Sphere` → 1 face, 0 edges, 2 vertices; `Torus` → 1 face, 0 edges, 1
vertex). Do not expect `EDGE_CURVE` count == `part.edges()` count for the closed
primitives.

## Topology conventions (same as smlibpy's `step.py`)

- **Cylinder lateral loop**: seam `.F.` (top → bottom), bottom circle `.T.`, seam `.T.`
  (bottom → top), top circle `.F.`. Cap loops: bottom circle `.F.` on a `-Z` plane, top
  circle `.T.` on a `+Z` plane.
- **Cone lateral loop**: same pattern; a missing cap omits its circle from the loop (apex
  case: seam `.F.`, base circle `.T.`, seam `.T.`). `CONICAL_SURFACE` is placed at the
  wide end, axis pointing outwards at that end, with a positive semi-angle
  `atan(|r_base - r_top| / height)` and the wide radius as the placement radius. This
  makes both taper directions work and keeps the semi-angle positive as STEP requires.
- **Sphere**: one seam circle in the `XZ` plane (placement axis `-Y`, reference `+X`),
  edge from the south pole to the north pole, face loop uses it `.F.` then `.T.`
  (`VERTEX_LOOP` is not needed; smlibpy does not write one either).
- **Torus**: tube seam circle at `(major, 0, 0)` with axis `-Y`, outer-equator circle at
  the origin with axis `+Z` and radius `major + minor`; the single seam vertex is
  `(major + minor, 0, 0)`; loop order tube `.F.`, equator `.T.`, tube `.T.`, equator
  `.F.`.
- **Faces** are `ADVANCED_FACE(..., .T.)` for every primitive, i.e. the face normal is
  the analytic surface's natural normal (outward). Cap planes carry outward normals
  (`-Z`/`+Z`).
- All files are `MANIFOLD_SOLID_BREP` inside one `CLOSED_SHELL`, with the AP214
  product/context/`SI_UNIT(.MILLI.,.METRE.)` header and file-level uncertainty `1e-6`.

## Trimmed planar faces with holes

`PlanarBody` keeps `faces: Vec<Vec<usize>>` (outer loops) for source compatibility with
`nodecraft-solidcore`/`nodecraft-worker` and adds an index-aligned
`holes: Vec<Vec<Vec<usize>>>`. Helpers: `push_face`, `face_holes`, `set_face_holes`,
`loops`, plus `triangulate`/`face_triangles` and `try_area`/`try_volume`; the older
`area()`/`volume()` are NaN when triangulation fails (never a silently holed result).
Bodies built by other crates may leave `holes` short; `face_holes` treats that as no
holes.

Reader (`planar_body_from_file`):

- collects both `FACE_OUTER_BOUND` and `FACE_BOUND`, storing the bound's loop id,
  kind and orientation flag;
- groups the bounds per `ADVANCED_FACE` (previously every bound became its own face —
  a hole would have been read as an extra face);
- a bound whose flag is `.F.` is reversed before use; `.T.`/missing is kept as written;
- requires exactly one usable outer bound: two outers or holes without an outer are
  explicit errors; an inner loop under three vertices is an error (not dropped);
- a non-polygonal outer bound (e.g. a single closed curve, as on curved primitive caps)
  still causes the face to be skipped, matching the previous planar-reader scope.

Writer (`write_planar_body`):

- one `ADVANCED_FACE` per face, a `FACE_OUTER_BOUND` plus one `FACE_BOUND` per hole, in
  stored order and always with orientation `.T.`; loop order is never changed, so a hole
  that is stored clockwise stays clockwise (orientation is preserved rather than
  "fixed");
- shared `EDGE_CURVE`s are created across all loops, keeping manifold edges;
- validates every loop before touching point data: at least three vertices, in-range
  indices, no consecutive duplicate points, coplanar with the outer loop (tolerance
  `1e-6 * bbox diagonal`), non-degenerate inner loops; the plane placement normal comes
  from the outer loop's Newell normal and the reference direction is orthonormalized.

Triangulation (`triangulate.rs`):

1. Project loops onto the face plane using the outer loop's Newell normal (2D basis is
   right-handed about it, so outer winding is counter-clockwise).
2. Normalize hole winding to clockwise for ear clipping (internal only).
3. Bridge each hole, in order, at its extreme +u vertex to the nearest visible ring
   vertex (segments must stay inside the ring, outside every hole and cross no edge);
   the bridge duplicates both endpoints, giving a zero-width corridor.
4. Ear-clip the resulting ring; ears must be convex, contain no other vertex and have
   non-zero area. A stall is an explicit error.
5. Check triangle area against `outer - holes` (`1e-9` relative); a mismatch is an error,
   not a wrong mesh. Area and volume are then derived from these triangles.

Measured trimmed case (`tests/trimmed_planar.rs`): 4x4x1 slab with a 2x2 through-hole
writes to 10 `ADVANCED_FACE`s (10 `FACE_OUTER_BOUND`, 2 `FACE_BOUND`), reads back with
holes index-aligned, area 48, volume 12; `smlibpy.import_step(heal=False)` returns a valid
solid with 10 faces / 24 edges / 16 vertices, volume 12, area 48, bounds
`(0,0,0)..(4,4,1)`. Rectangle-with-one-hole, two-hole and concave L-shape-with-hole
triangulations are checked triangle-by-triangle (centroid outside every hole, inside the
outer loop, area sum equals `outer - holes`).

## Limits / next steps

- Only closed **solids** are written. No sheets, no voids (`BREP_WITH_VOIDS`), no
  multiple bodies per file, no colors/styles, mm only.
- B-splines and arbitrary NURBS are not written; only the four analytic surfaces.
- `write_cone` accepts equal radii (zero taper) and either radius zero; both zero is
  rejected. `write_torus` rejects `minor >= major` (horn/spindle tori).
- The crate's STEP *reader* still only reconstructs planar topology; curved import stays
  with smlibpy/the Python worker.
- Worker wiring: `nodecraft-worker`'s `exporter` currently writes only a direct box
  source. The worker is owned by another agent; hooking its `primitive` match to these
  four writers (`primitiveType` → `write_*`) is the remaining integration step and needs
  no change in this crate.
- The existing `rust/scripts/step-conformance-output.py` drives the worker exporter; once
  the worker wires these writers, its cylinder/cone/sphere/torus cases should flip from
  `EXPECTED` to passing with the metrics above.

Trimmed-face limits:

- The worker's planar *import* mesh still iterates `body.faces` only, so holes are not
  rendered until the worker calls `triangulate()` (worker crate is owned elsewhere; the
  crate API is ready). Likewise `nodecraft-solidcore::planar_body` still pushes every
  B-rep loop as a separate face, so holes produced there do not reach the trimmed model
  yet.
- Nested holes (an island inside a hole), holes touching/overlapping the outer loop, and
  self-intersecting loops are not modelled; the bridge/ear-clip step returns an explicit
  error when it cannot produce a valid triangulation.
- The writer emits `.T.` bound flags and relies on stored loop order for orientation; it
  does not check whether an inner loop is actually inside the outer loop (triangulation
  is where that is exercised).
- STEP files are still written in mm only, closed shells only (no sheets/voids), and the
  planar reader still does not rebuild curved topology.


## ADVANCED_FACE same_sense

Newer SolidCore `step-brep` exports use the material face-use orientation, so a
valid solid can have `.F.` faces. The legacy planar body stores only loop order,
not per-face surface normals. `read_planar_body` therefore normalizes a closed
solid after reading: if its signed volume is negative, every outer and hole loop
is reversed. This exactly negates the signed volume and avoids a centroid
heuristic on multi-body or non-convex solids. SolidCore's own topology-first
builder reads the same files with positive volume, confirming the export is
valid.
